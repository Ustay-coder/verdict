# 스타일 가이드

## 문체
- 한국어 **합니다체**로 통일한다.
- 1인칭은 "저희 팀" 대신 "우리". 과장 표현(획기적, 압도적, 혁신)과 AI 투 서두("이번 글에서는 ~를 알아보겠습니다")를 쓰지 않는다.
- 문장은 한 가지 사실만 담는다. 주장 뒤에는 바로 수치나 예시를 붙인다.

## 구성 (모든 편 공통)
1. **한 줄 요약**: 이 글을 읽으면 알게 되는 것 1개.
2. **문제**: 측정으로 드러난 증상. 느낌이 아니라 수치.
3. **가설과 개입**: 무엇을 왜 바꿨는지. 코드 대신 *역할*로 설명한다.
4. **측정 결과**: 전 → 후 표 + 그래프 1개.
5. **남은 문제**: 해결하지 못한 것을 반드시 적는다.
6. **스코어보드**: 시리즈 공통 표(아래).
7. **다음 편 예고** 1~2문장.

## 수치 규칙
- 수치는 `facts.json`에 있는 값만 쓴다. 반올림은 소수 둘째 자리까지 원문 그대로.
- "개선"이라고 쓰려면 전·후 값을 함께 적는다.
- 판정 모델 점수는 실행마다 달라질 수 있음을 처음 등장할 때 한 번 밝힌다.

## 길이
본문 1,800~3,500자. 표와 코드 블록은 제외.
