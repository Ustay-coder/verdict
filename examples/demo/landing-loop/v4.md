# Verdict

## Turn your grading rubric into an API call: a score and a probability for every criterion, ~0.4 s per model call.

For developers who grade things in code: pitch decks, essays, support tickets, PRs, LLM outputs.
Replace "ask a chat model and parse its prose" with typed questions that return calibrated probabilities.

### Try it in one command, no account and no API key

```bash
git clone https://github.com/Ustay-coder/verdict && cd verdict && pnpm i && pnpm build && node packages/cli/dist/bin.js eval -r examples/rubrics/offline-benchmark.yaml -i ci=examples/inputs/ci.json -i examples/inputs/CHANGELOG.md
```

That rubric uses deterministic checks only, so it runs offline. Add `--mock` to any other rubric to dry-run it.

### What you get back (trimmed; a real run of a landing-page rubric)

```json
{ "aggregate": { "score": 98, "grade": "ship it", "passed": true },
  "criteria": [{ "criterionId": "value_prop", "score": 4.98, "normalized": 0.995,
                 "ratings": [{ "confidence": 0.98,
                               "probabilities": { "fog": 0, "category": 0, "what": 0, "what_who": 0.02, "sharp": 0.98 } }] }] }
```

### Measured, not promised

- **0.40 s**: one live Clef-flash call answering a whole rubric (HTTP 200, Cloudflare Workers AI).
- **1 request per judge, not per criterion**: every criterion that shares a judge and its evidence goes out together.
- **Confidence on every score**: below your `minConfidence`, the criterion is routed to a human reviewer instead of guessed.

### Why not just prompt a chat model?

A chat model gives you a paragraph and a number you have to parse. Verdict gives you a probability per rubric
level, a confidence, and a total from an aggregation you control: weighted mean, min, gates, or your own formula.
Change the formula later and re-rank old results without calling a model again.

### Works where your code is

REST API on Cloudflare Workers, CLI, MCP server for agents (Claude Code, Codex), TypeScript SDK. MIT licensed.
