# 초기창업패키지 요건검토: 신청서 120건

2026년 초기창업패키지(일반형) 모집공고의 **요건검토**를 Verdict로 해 본 예제다. 사업계획서가 잘 쓰였는지를 보지 않는다.
공고문이 정한 신청자격과 신청 제외 대상, 사업계획서 양식의 작성 규칙을 지켰는지만 본다. 담당자가 기업마다 한 건씩 확인하는
체크리스트다.

```bash
npm install -g @verdict-ai/cli
verdict run -r eligibility.yaml -d cases.jsonl --models jev            # TYPESAFE_API_KEY
verdict run -r eligibility.yaml -d cases.jsonl --models mock           # 키 없이: 규칙 7개는 그대로, 모델 답은 가짜
```

## 무엇을 보나

근거는 중소벤처기업부 공고 「2026년도 초기창업패키지(일반형) 창업기업 모집공고」의 3. 신청자격 및 요건, [붙임 3] 지원 제외
대상 업종, [붙임 4-1·4-2], 그리고 (별첨1) 사업계획서 양식의 작성 안내다.

| 검사 | 근거 | 누가 판정하나 |
| --- | --- | --- |
| 업력: 2023.1.23 ~ 2026.1.22 개업·설립 | 신청 자격 세부 조건 | 규칙 (날짜 비교) |
| 필수 서류: 신분증 사본, 사업자 증빙 | (별첨2) 증빙서류 제출목록 | 규칙 |
| 제외 업종 코드가 아님 (56211, 56212, 91242, 91249) | [붙임 3] | 규칙 |
| 휴·폐업이 아님 | 신청 제외 대상 ⑨ | 규칙 |
| 정부지원사업비 1억원 이내 | 사업계획서 양식 | 규칙 |
| 양식 항목(문제 인식·실현 가능성·성장전략·팀 구성) 유지 | 양식은 변경·삭제할 수 없음 | 규칙 |
| 양식 안내 문구(※) 삭제 | 파란색 안내 문구는 삭제 | 규칙 |
| 개인정보 블라인드 | 성명·성별·생년월일·학교·직장명 마스킹 | 모델 |
| 제외 업종을 영위하려 하지 않음 (사행성, 가상자산 거래) | 신청 제외 대상 ④⑩ | 모델 |
| 지원 이력상 제외가 아님 | 신청 제외 대상 ⑥⑦ | 모델 |

숫자·날짜·목록은 규칙이 계산하고, 문장을 읽어야 하는 세 가지만 결정 모델이 본다. 모델이 확신하지 못한 답(확률 0.25~0.75)은
판정하지 않고 **담당자 확인**으로 넘긴다(`minConfidence: 0.5`, `onLowConfidence: human`). 규칙이 오류를 내면 그 건은
통과가 아니라 미충족이 된다(`missing: fail`).

공고문에 있지만 이 예제가 보지 않는 것: 채무불이행·국세 체납·환수금·체불사업주처럼 기관 자료로만 확인되는 항목(①②③⑫⑬),
지원사업 3회 이상 수혜(⑤), 공동대표 전원의 자격 확인.

## 데이터: 가상 신청서 120건

[generate.mjs](generate.mjs)가 만든다. **모든 기업과 인물은 가상이다.**

1. `generate.mjs base`: 모델(gpt-5.4-mini)에게 요건을 모두 지킨 사업계획서 본문 120개를 받는다([base/](base)). 30개 분야를 돌아가며
   쓰고, 양식의 네 제목을 그대로 쓰게 했다. 모든 본문이 규칙 검사를 통과하는지 확인한 뒤에만 다음 단계로 간다.
2. `generate.mjs build`: 신청서(JSON)를 만들고, 정해진 기업에 위반을 하나씩 심는다. 날짜·값을 바꾸거나 정해진 문장을 넣는
   방식이라 정답이 만들 때 정해진다.

| | 건수 | 내용 |
| --- | --- | --- |
| 위반 | 52 | 13가지 × 4건. 규칙 위반 8가지, 모델이 읽어야 하는 위반 5가지 |
| 함정 | 20 | 위반처럼 보이지만 요건상 문제없는 5가지 × 4건: 마스킹된 이름·학교, 예비창업패키지 1회 선정, 지자체 사업 수행 중, 현금 없는 게임, 신청가능 업력 첫날 개업 |
| 깨끗함 | 48 | 위반도 함정도 없음 |

루브릭, 신청서, 정답, [PREDICTIONS.md](PREDICTIONS.md)는 모델을 부르기 전에 커밋했다(`ffc6b3d`). 규칙 7개는 그 전에
`--mock`으로 840개 답(120건 × 7개)을 정답과 맞춰 보았고 모두 일치했다.

## 실행 (2026-11-15)

전체 출력은 [run-2026-11-15.txt](run-2026-11-15.txt), 모든 답과 확률과 완료 시각은 [results.json](results.json)에 있다.

```
초기창업패키지 요건검토 × cases.jsonl: 120 case(s), 3 model(s), the same questions to each
  model        answered by             agreed with labels   failed   asked a human   input tokens   calls   time
  jev          typesafe/jev-1.14.0     1195/1195 (100%)     0        5               315,373        120     3.5 s
  clef-flash   cloudflare/clef-flash   1164/1165 (100%)     0        32              221,682        120     10.4 s
  clef         cloudflare/clef         1167/1167 (100%)     0        33              221,682        120     11.4 s
```

신청서 한 건 단위로 보면:

| | Jev | Clef-flash | Clef |
| --- | --- | --- | --- |
| 걸린 시간 (120건) | **3.5초** | 10.4초 | 11.4초 |
| 위반 52건 중 미충족으로 판정 | **52** | 41 | 45 |
| 위반을 통과시킴 | 0 | **1** | 0 |
| 위반이 있는데 담당자 확인으로 넘김 | 0 | 10 | 7 |
| 위반 없는 68건을 미충족으로 판정 | 0 | 0 | 0 |
| 담당자 확인으로 넘긴 건 | **5** | 25 | 24 |
| 자동 통과 | 63 | 53 | 51 |

- **Jev는 120건을 3.5초에 끝냈고, 판정한 1,195개 답이 모두 정답과 같았다.** 담당자에게 넘긴 5건은 모두 함정이었다.
  예비창업패키지 1회 선정 3건(제외 사유 아님), 마스킹된 이름·학교 2건(위반 아님). 사람이 다시 봐야 할 만한 문장이다.
- **Clef-flash는 가상자산 거래소를 열겠다는 신청서 한 건(008)을 83% 확률로 통과시켰다.** 확신한 오답은 담당자 확인으로도
  가지 않는다. 같은 신청서를 Jev는 미충족으로 판정했고, Clef는 담당자 확인으로 넘겼다.
- Clef와 Clef-flash는 각각 24~25건을 담당자에게 넘겼다. 그중 대부분은 위반이 없는 건이었다. 틀리지는 않았지만 일을 덜어 주는
  폭은 작다.

## 한계

- 신청서는 가상이고, 위반은 분명한 문장으로 심었다. 실제 신청서의 위반은 더 흐릿하다. 실제 서류에서 이 숫자가 그대로 나온다는
  뜻이 아니다.
- 사업계획서 본문은 4~6KB로, 실제(15쪽 내외)보다 짧다. 실제 분량에서는 시간과 결과가 달라질 수 있다.
- 시간은 이 컨테이너에서 각 서비스까지 잰 것이다. 네트워크와 서비스 상태에 따라 달라진다.
- 공고문 원문과 양식은 이 저장소에 넣지 않았다. [K-Startup](https://www.k-startup.go.kr) 공고 게시판에서 받을 수 있다.
