# 서류 검토 서비스 — UI 시안

> 산출물 B. 시안은 실제 앱과 **같은 React 컴포넌트**(`apps/review/web/src/components`)를 쓰고, 데이터만 개발용 모형(`web/src/dev/`)으로 바꾼 별도 엔트리 `prototype.html`이다. 운영 엔트리(`index.html` → `main.tsx`)는 `src/dev/`를 import하지 않는다.

## 2. 컴포넌트 구성 (shadcn/ui 기반)
| 컴포넌트 | 사용한 shadcn/ui | 역할 |
| --- | --- | --- |
| `AppHeader` | — | 서비스명, 단계 표시(`요건 · 서류 · 검토`, 지나온 단계는 클릭해 이동) |
| `RequirementStep` | `Textarea`, `Button` | 제목·입력·다음 |
| `UploadStep` / `DropZone` / `FileRow` | `Button`, `Separator` | 드롭 영역, 행 상태(진행 막대·스피너·오류+재시도), 이전·검토 시작 |
| `ReviewBoard` | `Card`, `Button` | 3열 레이아웃, 제어 버튼 |
| `Pile` | `Card` | 겹친 카드, 다음 파일명, 대기 수, 처리 오류 목록 |
| `CurrentDoc` | `Card` | 파일명, 단계 문구, 요건 행 |
| `ResultBin` | `Card`, `Button` | 판정명·건수·최근 5건·전체 보기 |
| `BinSheet`, `DetailSheet` | `Sheet`, `ScrollArea` | 전체 목록, 요건별 판정·근거 상세 |
| `FlightLayer` | — | 이동 중 복제 카드(화면 전용, 데이터에 추가하지 않음) |

판정 색: 충족 `emerald`, 미충족 `rose`, 확인 필요 `amber`, 오류 `destructive`. 색과 함께 항상 판정 문구를 표시.

## 3. 화면 전환
- 단계 전환은 같은 페이지 안에서 상태로 전환(라우터 없음). 전환 시 본문 제목/첫 컨트롤로 포커스 이동.
- 검토 단계 URL `?run=<id>`(새로고침 복구용).

## 4. 문서 이동 방식과 타이밍
| 모션 | 트리거(실제 이벤트) | 시간 | 이징 |
| --- | --- | --- | --- |
| 대기 → 중앙 | `doc.started` | 400ms | `cubic-bezier(.2,.7,.2,1)` |
| 중앙 → 결과 영역 | `doc.completed`(결과 저장 후 서버가 기록) | 500ms | 같음 |
| 도착 강조 | 이동 종료 | 700ms 배경 1회 페이드 | — |

- 구현: Web Animations API. 출발·도착 좌표는 매번 현재 DOM에서 `getBoundingClientRect()`로 계산(모바일 세로 배치도 동일 코드).
- 데이터 상태는 이벤트 즉시 반영하고, 복제 카드는 `FlightLayer`에만 존재(목록·건수에 영향 없음). 목적지 행은 이동 중 투명(`data-landing`)했다가 도착 시 보임 — 중복 표시 없음.
- 빠른 결과: 진행 중 비행이 2개 이상이면 새 비행 시간을 절반으로, 4개 이상이면 비행 생략(바로 강조만). 이전 비행이 끝나기를 기다리지 않는다.
- 복구(스냅샷 로드)·이미 완료된 문서·재연결 재전송에는 모션 없음.
- 회전·튕김·반복 점멸·파티클 없음.

## 5. 반응형 배치
- `lg`(≥1024px): `240px | 1fr | 340px` 3열.
- 그 미만: 대기 → 현재 문서 → 결과 3영역(세로, 결과 영역은 `sm` 이상에서 3열 가로) 순. 이동 좌표는 같은 방식으로 계산.
- 긴 파일명은 `truncate` + `title`.

## 6. 키보드·동작 줄이기
- 드롭 영역 `role=button`, Enter/Space로 파일 선택. 모든 버튼은 실제 `<button>`.
- 결과 목록 항목은 버튼, 상세 Sheet는 포커스 트랩·Esc 닫기·닫으면 원래 항목으로 포커스 복귀.
- 새 이벤트는 선택 문서·포커스를 바꾸지 않는다. 진행 상황은 `aria-live="polite"`(중앙 단계 문구, 건수).
- `prefers-reduced-motion: reduce`: 비행 생략, 도착 강조는 짧은 색 변화만. 상태·결과·문구는 동일.

## 7. 시안 실행·확인 방법
```bash
pnpm --filter @verdict-ai/review-app dev:web
```
- 시안: `http://localhost:5173/prototype.html` — 상단 개발용 막대에서 상태 선택(요건 입력 전/후, 업로드 전/파일 있음/진행·오류 행, 검토 시작, 순차 검토, 상세, 완료). 데이터·진행은 `src/dev/`의 예시와 타이머이며 **실제 검토가 아니다**.
- 운영 화면: `http://localhost:5173/`(서버 필요, [spec.md](spec.md) §8).
- 서버로 확인: `REVIEW_SERVE_PROTOTYPE=1`로 서버를 띄우면 `/prototype.html`도 열린다(운영 서버 기본값은 404).

## 8. 스크린샷 (`screens/`, 배율 2)
| 파일 | 내용 | 데이터 |
| --- | --- | --- |
| `proto-req-empty-*`, `proto-req-filled-*` | 요건 입력 전·후 | 시안 |
| `proto-upload-empty-*`, `proto-upload-files-*`, `proto-upload-progress-*` | 업로드 전, 파일 있음, 전송 진행·준비 중·오류+재시도 행 | 시안 |
| `proto-review-*`, `proto-review-sequential-*` | 검토 시작(요건 해석 직후), 순차 검토 중(도착 강조) | 시안 |
| `proto-detail-*`, `proto-done-*` | 결과 상세, 검토 완료 | 시안 |
| `real-1` ~ `real-8` | 운영 화면 + 실제 서버·모델: 요건, 업로드 진행, 오류 행, 검토 중, 검토 중 상세, 완료, 상세(근거·쪽), 모바일 완료 | **실제 검토** |

`*-desktop`은 1440×900, `*-mobile`은 390×844(전체 페이지). 생성: `node apps/review/scripts/screens.mjs <서버 주소>`, `node apps/review/scripts/e2e.mjs <서버 주소>`.
직접 열어 확인한 범위: 위 스크린샷 전부와 E2E가 조작한 흐름. 실제 터치 기기·스크린 리더로는 확인하지 않았다.
